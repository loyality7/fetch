Understanding Connection Pooling

Posted on 4 March 2026 by Editor

Opening a database connection is expensive. A pool keeps a set of established connections alive and hands them out on request, so the cost of the handshake is paid once rather than on every query. This matters most when queries are short and frequent.

When pooling stops helping

A pool sized larger than the database can serve does not make the system faster. It moves the queue from the application into the database, where it is harder to observe and where each waiting connection consumes server memory.

  • Size the pool to the database, not to the application
  • Measure wait time at the pool, not just query time
  • Fail fast when the pool is exhausted
maxPoolSize = min(cores * 2, dbMaxConnections / instances)
